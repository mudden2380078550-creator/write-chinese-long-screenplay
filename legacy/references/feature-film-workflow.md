# 中文电影剧本工作流

## 读取顺序

1. `project.md`
2. `background/story-background.md`
3. `bible/feature-bible.md`
4. 相关人物卡与世界规则
5. `outline/structure-map.md`
6. 当前序列和目标场次大纲
7. 最近两场正文与紧凑台账

不要在写单场时读取全部未来正文或全部作者适配器。

## 阶段一：材料正典

人物小传至少明确：

- 外在欲望、内在需要、错误信念和保护策略；
- 可调用资源、真实限制和不能使用的简单方案；
- 对其他人物的关系交换、秘密、知识边界和语言特征；
- 在压力下会先使用、何时放弃的策略。

背景和世界观只收录会改变选择、成本、风险、时间或空间的事实。装饰性设定不进入必读上下文。

## 阶段二：主题与行动线

填写：

- 主题命题：某种价值结果，因为人物如何行动；
- 反命题：相反价值结果，因为人物如何行动；
- 主角外在欲望、内在需要和核心行动线；
- 对抗力量的目标、正当性、资源和适应方式。

主题不能替人物作决定。必须由高潮行动提供最终证据。

## 阶段三：统一结构图

按 [core-story-engine.md](core-story-engine.md) 完成：

`激励性扰动 → 递进复杂化 → 不可回头点 → 危机选择 → 高潮行动 → 结局价值 → 余波`

为每个节点记录：

- 人物当时目标；
- 人物主动选择；
- 关闭的退路；
- 直接后果；
- 故事价值变化。

启用作者适配器时，只在统一结构完成后映射。适配器无法映射不自动表示故事错误；先判断是功能缺失还是结构不同。

## 阶段四：序列与逐场大纲

每个序列明确：

- 故事价值及进入/退出状态；
- 阶段任务；
- 对抗如何学习和加压；
- 关键选择与序列转折；
- 对下一序列造成的压力。

逐场大纲必须填写 v2 场景链：

`视点/目标 → 价值 → 冲突/策略 → 预期/实际/落差 → 转折 → 出场价值 → 下场压力`

若两场具有相同视点、目标、价值变化和下场压力，优先合并或删除。

## 阶段五：正文

单场写作：

1. 按场景风险选择 `scene-light`、`scene` 或 `scene-complex`。
2. 从来源事实提取当前可用的资源、限制、风险和误导。
3. 写人物行动与对抗反制，不写设定摘要。
4. 让结果落差迫使人物换招。
5. 用视听证据完成转折和观众更新。
6. 写入场次后立即更新台账。

连续 4–8 场写作：

1. 用 `--profile batch --scene-from N --scene-to M` 构建一次共享上下文；单批不得超过 8 场。
2. 按逐场大纲确定批次的起点状态、终点压力和不可提前泄露的信息。
3. 为第一场建立 `scene` 局部上下文并生成正文。
4. 写入正文并更新台账后，重新构建下一场局部上下文。
5. 普通过场可降为 `scene-light`；重大揭示、群戏或高潮升为 `scene-complex`。
6. 批次结束时检查每场的下场压力是否实际进入下一场，而不是只在场次卡中声明。

共享上下文只减少人物卡、世界规则和序列资料的重复装载，不能冻结批次内会变化的知识、关系、伤势、物件或线索状态。

对白场再读取 [dialogue-engine.md](dialogue-engine.md)。格式见 [chinese-screenplay-format.md](chinese-screenplay-format.md)。

## 阶段六：审查

按风险选择：

- 单场完成：`--focus scene`
- 对白密集序列：`--focus dialogue`
- 幕、序列或全片节点：`--focus structure`
- 改稿回归：`--focus continuity`
- 完整初稿：`--focus full`

每完成约 30 场，先运行严格校验，再按 `scene`、`dialogue`、`continuity`、`structure` 顺序审查已完成正文；先依据自动报告和场景证据索引定位问题，再读取相关序列和场次，不把30场全文无差别塞进一次语义审查上下文。

完成门槛：

- 所有场次具有来源、人物目标、结果落差和价值变化；
- 危机是人物必须承担代价的选择；
- 高潮使用已建立机制并造成最大价值变化；
- 余波展示新秩序，而不是重复解释高潮；
- 适配器警告已经判断并记录接受或修改理由。
