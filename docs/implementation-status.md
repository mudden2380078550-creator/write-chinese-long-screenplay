## 对重构方案的落实与调整

- T1/T2：保留原安装备份，建立兼容回归并修复已复现缺陷。源码来源许可文件缺失已在NOTICE记录，未擅自改许可。
- T3/T4：实现独立Python包与显式字段/领域校验。为离线可用选择标准库实现，提供交换Schema，不引入第三方JSON Schema解释器；不声称支持任意Schema执行。
- T5：实现本机文件锁、版本检查、恢复日志和幂等接受；不提供分布式锁。
- T6：小说有独立章节接口与无剧本限制的正文。新v3剧本提供基础正文规则；完整旧电影/剧集场次校验保留在v2兼容层，未把所有旧场次卡约束强加给小说。
- T7/T8/T9：实现历史查询、修订副本、完整必要上下文与统一接受流程。未来实体引用无法从历史满足时明确阻断，交作者调整修订基础。
- T10：用户自然语言入口由Skill承接，提案由宿主填写；核心可靠归档与检查，不内置外部模型调用。
- T11：复制迁移保留原件并标注未知历史。旧harness条目须经审定进入新模型；不会从旧通用字典自动推断作者政策与实体含义。
- T12：本地验证、打包、双语说明与CI配置已交付。跨平台实跑、多真实AI评估和外部发布属于尚未验证部分，不能将其标为完成。

## 当前限制

1. 规则检索以章纲实体引用、归属与依赖为主；自由文本含义仍由宿主整理，原资料不会自动全部进入上下文。
2. 自由文本政策、隐喻式技能使用和人物知识语义需要审稿；正则只提供线索。
3. 正式文件被手工改动会拒绝继续；保留编辑内容，用作者配置或候选重新提交，不要改哈希清单绕过。
4. 历史未知的迁移章节不能伪造写前状态；迁移报告有未审旧数据时新稿生成阻断，需显式migration-confirm审定记录。
5. 外部发行前需要恢复并核对原始LICENSE文件；本轮只做本机安装，未发布仓库、PR或发行版。

## 恢复与后续维护

作品有未完成事务时执行project recover，再doctor。Skill需要退回旧版时使用上述完整备份，先保存当前安装副本，避免丢失后续修改。工具升级后重新安装Skill副本；作品通过harness.lock.json声明当前匹配版本。

后续优先用真实短篇样本做宿主行为回归，观察资料提案、引用召回和语义审查表现，再扩大到长连载；不要因为工程测试通过就批量生成大量正典。
