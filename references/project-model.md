# v2 项目模型

## 正典优先级

1. 用户当前明确指令；
2. 锁定正文和已确认台账；
3. 人物、背景、世界规则等来源文件；
4. 统一结构图、序列和逐场大纲；
5. 作者适配器映射和诊断建议。

低层级不得静默覆盖高层级。大纲与正文冲突时，先判断正文是已确认创作还是误写，再决定回写或修订。

## 项目契约

`project.md` 必须包含：

```yaml
schema_version: 2
story_engine: causal-value
structure_adapters: []
```

允许的适配器只有 `field`、`mckee`、`save-the-cat`。剧集可以保留空列表，但电影作者适配器不得强制套用到整季或单集。

## 三种知识

- 作者真相：项目正典中客观成立的事实；
- 人物知识：某人物在某场开始前已经获得并相信的内容；
- 观众证据：正文已经提供、观众可以观察和推断的内容。

三者分别维护。人物不知道的真相不能成为其策略依据；观众不知道的真相不能被当作悬念已经成立的证据。

## 场次正典

只有 `screenplay/scenes/` 中符合命名和 schema 的文件进入编译。场次卡是生成与审查契约，正文是已经发生事实的最高项目证据。

场次结果至少更新相关台账：

- 状态、知识、关系、物件、线索、线程；
- 故事价值与人物决定；
- 观众证据、开放问题和不确定内容。

## 修改

改稿前记录：

- 根因场；
- 要改变的目标或价值链；
- 锁定事实；
- 受影响的后续场次和台账条目；
- 回归检查范围。

不得覆盖已有场次文件。需要替换时先由用户明确授权，并保留修订记录。
